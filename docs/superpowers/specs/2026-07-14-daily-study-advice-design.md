# 每日 AI 讀書建議設計

**日期：** 2026-07-14  
**狀態：** 已實作並驗證

## 目標

在首頁的「今日讀書計畫」中，加入每天固定的一段讀書建議與鼓勵文字。內容要依考試倒數天數、到期複習題數、錯題題數與新題題數調整，但不得影響既有的複習排序、每日題量或作答紀錄。

## 使用者體驗

1. 使用者設定考試日期後，首頁會先顯示既有的倒數與題量。
2. 每天第一次取得讀書計畫時，系統依當日計畫產生一段「今日建議」。
3. 同一天再次開啟首頁，顯示完全相同的建議，不重複呼叫 AI。
4. 隔天首次開啟時，以新日期與當日題量產生新的建議。
5. 使用者變更考試日期後，當天的建議必須依新日期重新產生，不可沿用舊倒數的內容。
6. 未設定考試日期時，顯示引導設定日期的本機文字；考試日當天或已過期時，顯示以休息與整理為主的本機文字。

## 文案範圍

建議文字只可使用下列彙總資料：

- 距離考試的天數
- 到期複習題數
- 錯題加強題數
- 新題練習題數
- 今日總題數

文字應包含：

- 對目前倒數節奏的簡短說明
- 今日建議的作答順序，優先到期複習、再錯題、最後新題
- 一句務實、簡短的鼓勵

不得產生考題答案、法規解釋、虛構學習數據，或將 AI 內容標示為原始資料。

## AI 與替代機制

後端沿用既有本機 OpenAI 呼叫方式，API Key 僅從 `.env` 讀取，不傳給前端。

- 有可用 API Key 時：要求模型只根據計畫彙總資料，回傳繁體中文的短建議。
- 沒有 API Key、呼叫失敗、逾時、回覆空白或格式不合時：使用本機產生的替代文案。
- 替代文案使用相同的天數與題量資料，因此不論 AI 是否可用，讀書計畫都可正常使用。
- 畫面不顯示 AI 錯誤訊息，僅將建議標示為「今日建議」，避免干擾刷題流程。

## 資料與快取

新增本機資料表保存每日建議，至少包含：

- 產生日期
- 目前考試日期
- 目前計畫摘要的識別值
- 建議文字
- 來源（`ai` 或 `fallback`）
- 建立時間

當日期、考試日期或計畫摘要改變時，系統重新產生並保存該日建議。相同條件下直接讀取已保存內容。資料會納入完整 JSON 備份；備份資料結構版本升級時，舊版備份仍需可還原，缺少每日建議時視為尚未產生。

## 介面與 API

- `GET /api/study-plan` 的回應新增每日建議欄位，前端不需要新增獨立請求。
- 讀書計畫卡片在每日題量與「開始今日計畫」按鈕之間，增加易讀的「今日建議」區塊。
- 手機版以一般段落呈現，避免固定高度、截斷或擠壓按鈕。
- 儲存考試日期後，同一 API 回應應包含依新日期建立的建議或可立即建立的計畫資料。

## 錯誤處理

- AI 服務失敗時，記錄可辨識的後端錯誤資訊，但 API 仍回傳成功的讀書計畫與本機替代文案。
- 資料庫快取異常時，不回傳過期或不相符的建議；以本機替代文案維持畫面可用。
- 不記錄 API Key、題目內容、Cookie、Token 或登入資料。

## 驗收與測試

1. 同日、相同計畫連續讀取兩次，回傳相同建議且只產生一次。
2. 日期跨日、考試日期變更或題量改變時，會取得符合新條件的建議。
3. 未設定 API Key 與模擬 AI 失敗時，仍回傳包含倒數與題量的可讀替代文案。
4. 未設定考試日期與考試日當天，維持既有引導與休息文案。
5. JSON 匯出、預覽與還原包含每日建議；舊版本備份仍可還原。
6. 前端測試驗證建議區塊存在、內容不遮擋題量與開始按鈕。
7. 在 iPhone 16 Pro `402 x 874` 與桌面尺寸檢查首頁，確認文字無截斷、溢出或按鈕覆蓋。
