# 考試倒數與智慧讀書計畫設計

**日期：** 2026-07-14  
**狀態：** 已實作並驗證  
**範圍：** 人身保險私人題庫網站的本機讀書計畫功能

## 目標

讓使用者設定考試日期後，網站依題庫、作答紀錄與複習到期狀態，自動安排每日可執行的刷題順序。首頁可直接啟動今日計畫；既有的一般練習、錯題、常錯題與正式模考維持原有用途。

系統的排程結果必須可重現且不依賴外部 AI 服務。若本機已設定 OpenAI API Key，才可額外產生說明文字；此文字只說明系統已算出的安排，不改變題目、答案、法規或排程判定。

## 非目標

- 不建立日曆同步、通知、帳號或雲端資料傳輸。
- 不增加題目上傳、外部題庫擷取或瀏覽器擴充功能。
- 不更改正式模考的科目、題數、時間與通過規則。
- 不把未作答或只查看答案的行為記為答錯。

## 使用流程

1. 使用者在首頁的「今日讀書計畫」設定考試日期。日期必須是今天或未來日期。
2. 網站立即顯示考試日期、倒數天數，以及今天的複習、錯題與新題數量。
3. 使用者按下「開始今日計畫」，系統以固定順序建立一個練習階段：到期複習題、錯題加強題、再加入新題。
4. 一般練習沒有時間限制，使用者可直接查看答案；正式模考仍只能在交卷或時間到後看結果。
5. 每次作答後，系統更新該題的下一次複習時間；回到首頁時會重新計算今天的安排。

若題庫為空，首頁仍可設定考試日期與顯示倒數，但「今日讀書計畫」會顯示尚無可安排題目，且不建立空白練習。

## 排程規則

### 題目分類與優先順序

每次計算今日計畫時，以未標記「已掌握」的題目為範圍，依序選取：

1. 複習到期題：下一次複習日為今天或更早的題目。
2. 錯題加強：曾答錯且尚未列為到期複習題的題目。
3. 新題：從未有「answer」作答紀錄的題目。

同一題在一份今日計畫中最多出現一次。已掌握題不進入自動計畫，但歷史紀錄保留不刪除。

### 作答後的複習間隔

| 行為 | 下一次複習 |
| --- | --- |
| 答錯 | 隔天 |
| 第一次答對 | 3 天後 |
| 連續第二次答對 | 7 天後 |
| 連續第三次以上答對 | 14 天後 |
| 只查看答案 | 隔天，標記為待複習 |

「連續答對」只計算實際作答事件；答錯或只查看答案都會重設連續答對次數。正式模考提交時的作答也會更新複習狀態，因為它同樣反映使用者的實際答題結果。

### 每日數量與倒數調整

每日題數由目前可用題目量和剩餘天數決定，計算時不會超過可用題數。若剩餘天數小於或等於 0，系統只顯示考試日已到，不建立新的今日計畫。

| 倒數區間 | 今日安排 |
| --- | --- |
| 8 天以上 | 先完成到期複習與錯題，再以新題補足每日平均進度。 |
| 3 至 7 天 | 到期複習與錯題優先，新題只補足必要進度；首頁提示每兩天可進行一次正式模考。 |
| 1 至 2 天 | 不主動安排新題，集中到期複習、錯題與常錯題；首頁提示可進行正式模考。 |

每日平均進度以「尚未作答的新題 / 含今天在內的剩餘天數」向上取整計算。到期複習和錯題不會因平均進度而被截斷；若題量過多，首頁會如實顯示，不假裝可以在一天內完成。

## 資料與 API

新增兩個本機 SQLite 資料表：

- `study_plan_settings`：單一設定列，保存 `exam_date` 與更新時間。
- `review_schedules`：以題目為單位保存 `due_date`、`consecutive_correct`、最後排程原因與更新時間。

此資料只保存在本機 SQLite 與既有 JSON 備份中。修改資料庫結構採新增資料表，不刪除、不重設既有題目或作答紀錄。

新增或擴充的 API：

- `GET /api/study-plan`：回傳考試日期、倒數、今日任務數量、可執行題目數與安排說明。
- `PUT /api/study-plan/settings`：驗證並保存使用者輸入的考試日期，回傳重新計算的計畫。
- `POST /api/practice-sessions`：新增 `study-plan` 模式，由資料庫取得今日計畫的去重題目清單；預設不隨機題目與選項，讓複習順序可預期。
- `POST /api/attempts` 與正式模考交卷流程：完成原本的作答紀錄後，同步更新 `review_schedules`。

備份格式升級為 `schemaVersion: 2`，新增讀書計畫設定與複習排程資料。還原前仍先預覽並建立既有的安全備份；版本 1 備份可讀取並以空白讀書計畫設定還原，不能造成資料遺失。

## 首頁介面

首頁統計資料下方新增一個非巢狀卡片的「今日讀書計畫」區塊：

- 標題列顯示倒數，例如「距離考試 11 天」，並提供日期輸入欄位及編輯圖示。
- 顯示「到期複習」、「錯題加強」、「新題練習」三個明確數量，不以含糊的 AI 分數取代。
- 顯示一段簡短的安排理由，例如「先處理 12 題到期複習，再完成 8 題新題」。
- 有可直接開始的「開始今日計畫」按鈕。題庫不足時按鈕不可用並顯示原因。
- 模考只以簡短提示出現在倒數建議中，不會自動啟動或取代今日練習。

在 402 x 874 的手機畫面，日期欄位、任務數字與開始按鈕必須可完整閱讀與點選；桌面版維持目前置中的應用程式寬度，不拉成行銷式大版面。

## 錯誤處理

- 無效日期、空日期或過去日期：不寫入資料庫，回傳明確欄位錯誤。
- 題庫為空或今日沒有可排題目：回傳有效的零任務計畫，不建立練習階段。
- 題目已標記掌握、已從資料庫刪除或重複出現在候選清單：開始練習前再次去重與排除。
- OpenAI API 未設定、逾時或回應不完整：只省略 AI 補充說明，核心排程不受影響，也不自行編造內容。

## 測試與驗收

1. 資料庫測試：考試日期保存、日期驗證、倒數計算、三種題目選取順序與去重。
2. 排程測試：答錯、第一次答對、連續答對、查看答案與正式模考作答都產生正確的下一次複習日。
3. API 測試：今日計畫、設定日期、空題庫與 `study-plan` 練習階段的回應正確。
4. 備份測試：版本 2 可匯出與還原讀書計畫；版本 1 可安全預覽及還原既有資料。
5. 前端測試：首頁可設定日期、顯示零題提示、顯示任務數量並開始今日計畫。
6. 迴歸測試：既有順序、隨機、錯題、常錯題、查看答案與固定模考測試全部通過。
7. 視覺驗收：iPhone 16 Pro `402 x 874`、一般手機與桌面尺寸下，首頁、練習頁與答案展開後均無水平溢出、文字遮擋或按鈕重疊。

## 影響範圍

預計調整資料庫、API、備份格式、首頁、練習模式與對應測試。既有題目、選項、答案、解析、作答歷史、模考規則及使用者已掌握標記皆保留。
